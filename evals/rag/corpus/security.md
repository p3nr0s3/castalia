# Request protection
Every request passes through middleware. First the Host header is checked against an allow-list, which defeats DNS rebinding, because an attacker's domain cannot forge the Host header. Second, state-changing requests must be same-origin, using Sec-Fetch-Site, which stops cross-site request forgery. Third, an optional bearer access token guards the API. Outbound fetches for webhooks and web scraping use an SSRF guard: the hostname is resolved once, every address is checked, internal and private ranges such as 10.0.0.0/8 and 169.254.169.254 are blocked, and the connection is pinned to the validated address.
